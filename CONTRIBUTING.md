# Contributing

Contributions are welcome while the curriculum is being built.

## Before contributing

Please keep these distinctions clear:

- **Competency** — what a learner should know or be able to do.
- **Resource** — material used to learn or practice that competency.
- **Assessment** — evidence that the competency has been reached.

A new resource does not automatically require a new curriculum topic.

## Proposing a resource

Include:

- title and URL
- author or organization
- the competency it supports
- whether it is best used as primary, visual, practice, or reference material
- why it adds value beyond resources already listed

Prefer official course pages, textbooks, documentation, papers, and maintained repositories where possible.

## Proposing a curriculum change

For a new required topic, prerequisite change, or learning-outcome change, include:

- the problem or missing competency
- supporting curriculum, industry, or technical sources
- the proposed change
- affected prerequisites or downstream topics
- alternatives considered

Large changes should be discussed before a large pull request is opened.

## Writing and layout

Follow [AGENTS.md](AGENTS.md) for repository writing and presentation rules.

Public-facing documentation should be concise, navigable, and based on patterns used by established open-source learning repositories. Avoid promotional or generic AI-generated copy.

## Pull requests

Keep pull requests focused. A resource update, curriculum change, and repository refactor should usually be separate changes when they can be reviewed independently.
